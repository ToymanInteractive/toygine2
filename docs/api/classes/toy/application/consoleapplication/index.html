Description​

Abstract application object for a program that reports through the system console.

Extends toy::application::BaseApplication with two pairs of write calls: one pair for the output stream, one for the error stream. In each pair, one call writes the text as is and the other ends the line after it. A program derives from it, implements runInternal(), and expands IMPLEMENT_CONSOLE_APP to get main().

Key Features​

Derived-only construction: the constructor is protected and runInternal() stays pure virtual, so only a derived application can exist. Constexpr support: construction evaluates in a constant expression, so a derived application can be a constexpr object. Separate streams: writeOutput() and writeError() keep regular output apart from diagnostics. Line variants: writeOutputLine() and writeErrorLine() end the line after the text. Text input: each write call takes any toy::StringLike text, toy::String and toy::StringView included. Static output: no write call needs an instance, so code without access to the application object can write. Base services: version(), run(), the argument accessors, pid(), sleep(), and yield() come from toy::application::BaseApplication.

Usage Example​

 #include "application.hpp"
 
 class ConsoleSampleApp final : public toy::application::ConsoleApplication {
 public:
  explicit ConsoleSampleApp(const toy::application::Version & version) noexcept
  : ConsoleApplication(version) {}
 
 private:
  bool runInternal() noexcept override {
  writeOutputLine(toy::StringView{"Hello world from Console sample app"});
 
  if (argsCount() < 2) {
  writeError(toy::StringView{"Missing config: "});
  writeErrorLine(toy::StringView{"settings.cfg"});
  return false;
  }
 
  return true;
  }
 };
 
 IMPLEMENT_CONSOLE_APP(ConsoleSampleApp)

Performance Characteristics​

Construction: O(1); copies the version, as toy::application::BaseApplication does. Output: O(1) to wrap the text in a toy::StringView; the platform console does the rest. Memory usage: the size of toy::application::BaseApplication; the class adds no data members.

Safety Guarantees​

Contracts: the header checks none; the constructor accepts any version. Thread safety: the write calls may run on several threads at once. Each call holds a lock while it writes the text and the line end, so two calls on the same stream never interleave their output. Real-time use: a write call waits for the lock and for the console, so it does not belong in the frame loop or the audio callback. Exception safety: no operation throws; exceptions are off in the build.

Compatibility​

Console output: the write calls have an implementation on Windows, Linux, and macOS; on other targets a call fails to link. Entry point: IMPLEMENT_CONSOLE_APP defines the entry point on Windows, Linux, and macOS; on other targets expanding it fails the build.
