Description​

Owning, null-terminated byte string over a character buffer that a template argument chooses.

Follows the std::basic_string interface for char, with failure reported through assert_message instead of exceptions. The storage decides where the characters live and whether the string can grow: toy::FixedString keeps them inside the object and allocates nothing.

Template Parameters
storageType

Buffer that holds the characters, the terminator, and the length; satisfies toy::StringStorage.

Key Features​

Storage by template argument: the same interface over a fixed buffer or any other toy::StringStorage, so the choice between a heap and none stays out of the calling code. Standard interface: construction, assignment, element access, modifiers, search, comparison, and the free functions follow std::basic_string, with toy::StringLike types taking the place of string views. Counted length: size() decides what every operation reads, so a '\0' inside the string is an ordinary character, as in std::basic_string. Null-terminated: c_str() always reaches a terminator, so the buffer goes to a C interface unchanged. Constexpr support: every operation evaluates in a constant expression. Shared algorithms: search and comparison run the toy::string_utils functions that toy::StringView uses. Exception safety: no operation throws; exceptions are off in the build.

Usage Example​

 #include "core.hpp"
 
 toy::FixedString<32> name("player");
 name += " one";
 
 const size_t space = name.find(' ');
 const bool isPlayer = name.starts_with("player");
 const auto number = name.substr(space + 1);
 const toy::StringView tail = name.subview(space + 1);
 
 erase(name, ' ');
 const bool joined = name == "playerone";

Performance Characteristics​

Element access, size(), and c_str(): O(1). Copy and move: whatever the storage costs; toy::FixedStringStorage copies the whole object up to toy::platform::c_inlineCopyMaxBytes and the characters in use above it, and has no buffer to hand over on a move or a swap. Append and push_back: O(m) in the characters added, plus whatever growing the storage costs; nothing for toy::FixedStringStorage. Insert, erase, and replace: O(n) in the characters that move behind the edited range. Substring search: O(n * m) in the length of the string and of the pattern; nothing is indexed between calls. Character-set search: O(n + m) in the length of the string and the size of the set; each call builds one membership table, 256 bytes on the stack. Comparison: O(n) in the shorter length; equality stops on a length mismatch before reading a character. Memory usage: the size of storageType; for toy::FixedString, its buffer and one length field.

Safety Guarantees​

Contracts: offsets, capacities, and null pointers are checked by assert_message in debug builds. Every postcondition assumes the preconditions of its member held. A shipping build skips the checks: an edit the storage rejects leaves the string unchanged, and an offset past the end selects an empty range; each member states which. Allocation: the string allocates only where its storage does; toy::FixedString never does. Iterator validity: a call that grows the string may move the buffer of a storage that reallocates; toy::FixedStringStorage never moves it. Type safety: construction and assignment from nullptr are deleted, so the null case fails to compile. Exception safety: no operation throws; exceptions are off in the build.

Compatibility​

Over toy::FixedString no operation allocates or calls into the platform, so the type suits embedded and retro targets.

info

warning
