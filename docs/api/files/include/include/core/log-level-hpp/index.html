Description​

Severity scale of the logging module and the macro that trims it at build time.

Defines toy::log::Level, the scale every log call carries, and LOG_MAX_LEVEL, the number a call's level must not exceed to reach the binary.

info

Included by core.hpp only; do not include this file directly.

Enumerations​

Level​

enum class toy::log::Level : int8_t
 strong

Severity of a log message, ordered by verbosity.

Enumeration values
OffNothing passes (= 0)
ErrorFailed operation; execution may continue (= 10)
WarnCondition the engine recovered from (= 20)
InfoMilestone of normal operation: subsystem start, asset load (= 30)
DebugCoarse diagnostic detail, read while developing the engine (= 40)
TraceFiner detail than toy::log::Level::Debug, down to a single call or frame (= 50)

toy::log::Level::Off admits nothing, toy::log::Level::Trace admits everything, and the values between them grow with detail. A message passes a ceiling when the number behind its level is at most that ceiling.

Steps of ten leave room for a severity between two neighbors. The values are contract wherever a level is stored or transmitted: never renumbered, never reused.

info

toy::log::Level::Off is a ceiling value only; no message carries it as its own severity.

Macro Definitions​

LOG_MAX_LEVEL​

#define LOG_MAX_LEVEL   50

Number of the most verbose toy::log::Level a build keeps.

A call reaches the binary when its level is at most this value; anything more verbose compiles out. Define it ahead of core.hpp, on the compiler command line or in the target's CMake definitions, to cut the verbose end of the scale on a constrained target. It defaults to 50, the value of toy::log::Level::Trace, which keeps every level.

info

A number rather than an enumerator, so a build system sets it without toy::log::Level in scope.

info

Fixed at compile time; nothing raises the ceiling at runtime.
