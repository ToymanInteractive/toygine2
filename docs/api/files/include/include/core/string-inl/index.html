operator+()​

template <StringStorage storageType, StringLike StringType>
String< storageType > toy::operator+ (String< storageType > lhs, const StringType & rhs)
 nodiscard constexpr noexcept

Returns lhs followed by the characters of rhs.

Takes lhs by value: an lvalue is copied and an rvalue moved, so a chain such as a + b + c appends into one string, as the rvalue overloads of std::basic_string do.

Template Parameters
storageType

Storage of the string operand and of the result; satisfies toy::StringStorage.

StringType

Type of the right side; satisfies toy::StringLike.

Parameters
lhs

String to append to.

rhs

View or string to append.

Returns

lhs with the characters of rhs after its own.

Precondition

The storage accepts the joined length, checked by assert_message in debug builds.

warning

A shipping build skips the capacity check, and the result keeps the left side alone when the storage rejects the joined length, where std::basic_string throws std::length_error. A toy::FixedString built from a character array has no room left, so joining anything to it fails.

 nodiscard constexpr noexcept

Orders lhs against rhs lexicographically.

Orders as toy::String::compare() does: bytes as unsigned char, then length. The compiler derives <, <=, >, >=, and the reversed operand order from this operator.

erase_if()​

template <StringStorage storageType, typename Predicate>
String< storageType >::size_type toy::erase_if (String< storageType > & string, Predicate predicate)
 constexpr noexcept

Removes every character of string that predicate accepts.

Keeps the order of the remaining characters and moves them toward the front in one pass. The predicate runs once per character, through std::ref, so the copies the algorithm makes share one object.
