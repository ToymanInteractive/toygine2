secondByteRange()​

ByteRange toy::string_utils::anonymous{string_utils.cpp}::secondByteRange (uint8_t leadByte)
 nodiscard constexpr noexcept

Returns the range the byte after leadByte may take.

Four lead bytes narrow that range, which is what rejects the ill-formed sequences the lead byte alone admits (Unicode table 3-7). Read through wellFormedLength() by toy::string_utils::validateUtf8() and toy::string_utils::utf8ToUtf16(); the counting walk does no range check.

Parameters
leadByte

First byte of the sequence.

Returns

Range of the second byte, continuationRange for a lead byte that narrows nothing.

wellFormedLength()​

uint8_t toy::string_utils::anonymous{string_utils.cpp}::wellFormedLength (const char * str, size_t available)
 nodiscard noexcept

Measures the well-formed sequence that starts at str.

Checks the lead byte, the narrowed range of the byte after it, and the 10xxxxxx form of the rest. A terminator inside the sequence falls outside every range, so a walk over a null-terminated string stops at it.

Parameters
str

First byte of the sequence.

available

Number of readable bytes starting at str.

Returns

Length of the sequence in bytes, or 0 when it is ill-formed or does not fit in available bytes.

Precondition

available is at least 1.

Measures the well-formed UTF-16 character that starts at str.

A terminator is never a low surrogate, so a walk over a null-terminated string stops at a high surrogate before it.

This lookup table maps each of the 256 possible byte values to the length of a valid UTF-8 sequence that byte may begin, or to 0x00 when the byte can never start one. It gives O(1) lead-byte classification instead of O(n) bit-by-bit analysis.

info

Values: 0x01 = 1-byte ASCII, 0x02-0x04 = length of a multi-byte sequence this lead byte may begin, 0x00 = byte that can never start a valid sequence — continuation bytes (0x80-0xBF), overlong 2-byte leads (0xC0-0xC1), and out-of-range leads (0xF5-0xFF).

info

Range and overlong checks that depend on continuation bytes (e.g. for 0xE0, 0xED, 0xF0, 0xF4) are left to toy::string_utils::validateUtf8(); this table validates only what the lead byte alone determines.
