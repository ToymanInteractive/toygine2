Description​

Abstract application object that runs the program body and holds the version of its build.

A program derives from it and implements runInternal(). The entry point constructs the derived application from a toy::application::Version, then calls run() with the command-line arguments. No setter changes the stored version; assigning another application replaces the whole object, version included.

Key Features​

Derived-only construction: the constructor is protected and runInternal() is pure virtual, so only a derived application can exist. Constexpr support: construction and version() evaluate in a constant expression, so a derived application can be a constexpr object. Read-only version: version() returns a const reference, and the class has no setter. Command-line arguments: run() stores them, and argsCount(), args(), and arg() read them back. Process ID: pid() reports the ID of the running process and needs no instance. Thread suspension: sleep() and yield() hand the calling thread back to the scheduler and need no instance.

Usage Example​

 #include "application.hpp"
 
 class ToolApplication final : public toy::application::BaseApplication {
 public:
  explicit constexpr ToolApplication(const toy::application::Version & version) noexcept
  : BaseApplication(version) {}
 
 private:
  bool runInternal() noexcept override {
  return argsCount() > 1;
  }
 };
 
 int main(int argc, char * argv[]) {
  ToolApplication app{toy::application::Version{26, 20, 0, "f7e57d4"}};
 
  return app.run(static_cast<size_t>(std::max(0, argc)), argv) ? EXIT_SUCCESS : EXIT_FAILURE;
 }

Performance Characteristics​

Construction: O(1); copies the version, not the revision characters. Access: O(1); version(), argsCount(), args(), and arg() read stored values. Run: one virtual call to runInternal() per run() call. Memory usage: one toy::application::Version, the argument count and pointer, and the virtual table pointer.

Safety Guarantees​

Lifetime: the stored revision and arguments point to memory the application does not own. That memory has to outlive the application, as a string literal and the arguments main() receives do. Contracts: arg() checks its index against argsCount() with assert_message in debug builds; a shipping build returns nullptr instead. Memory safety: nothing allocates; run() stores the argument pointer without copying the arguments. Exception safety: no operation throws; exceptions are off in the build.

Protected Destructor​

~BaseApplication()​

toy::application::BaseApplication::~BaseApplication ()
 protected default

Destroys the application.

Only a derived application can destroy the base: deleting an application through a pointer to the base does not compile. Without a virtual destructor, the virtual table holds no call to operator delete, so targets without a heap link without it.

pid()​

uint32_t toy::application::BaseApplication::pid ()
 nodiscard noexcept static

Returns the ID the operating system assigned to the running process.

Each call queries the platform; read the ID once at startup and keep it.

Returns

Process ID, or 0 when the target has no implementation or the system call fails.

к сведению

Returns 0 on Sega MD, Nintendo GBA, Nintendo DS, Nintendo 64, Nintendo GameCube, Nintendo Wii, and Nintendo Wii U, where the build links the stub implementation.

к сведению

On Nintendo Switch, the result holds only the low 32 bits of the 64-bit process ID.
