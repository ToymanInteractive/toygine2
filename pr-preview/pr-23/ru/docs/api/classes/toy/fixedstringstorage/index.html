Description​

Character buffer of a compile-time size that keeps the string in it null-terminated.

Holds the characters inside the object and allocates nothing. One of the AllocatedSize bytes belongs to the terminator, so capacity() reports one less. The class writes no characters of its own: a caller fills the buffer through data() and then records the new length through setSize(), which puts the terminator behind it.

Template Parameters
AllocatedSize

Size of the buffer in bytes, the terminator included. Must be greater than 0, checked by a static assertion.

Key Features​

No allocation: the buffer lives inside the object, so the type works on targets without a heap. Compile-time capacity: AllocatedSize fixes the buffer once, and capacity() reports it minus the terminator. Explicit length: content and length move separately: the caller writes through data() and records the result with setSize(). Null-terminated: setSize() writes the terminator, so data() stays valid input for a C interface. Constexpr support: every operation evaluates in a constant expression. Exception safety: no operation throws; exceptions are off in the build. Storage concept: models toy::StringStorage, so a string constrained on it accepts this buffer. Checkable capacity: reserve() answers whether a length fits before setSize() commits to it.

Usage Example​

 #include "core.hpp"
 
 toy::FixedStringStorage<32> storage;
 
 storage.data()[0] = 'h';
 storage.data()[1] = 'i';
 storage.setSize(2);
 
 const size_t length = storage.size(); // 2, and storage.data() reads "hi"

Performance Characteristics​

Default construction: O(1); only the first byte is written, except in constant evaluation. Access and length: O(1) for data(), capacity(), size(), and setSize(). Copy and assignment: a whole-object copy up to toy::platform::c_inlineCopyMaxBytes, O(size()) above it. Memory usage: AllocatedSize bytes of characters and one length field, the object aligned as size_t.

Safety Guarantees​

Contracts: setSize() checks its argument against capacity() with assert_message in debug builds. A shipping build skips the check, and a length past the buffer writes the terminator out of bounds; reserve() is how a caller keeps that from happening. Bounds safety: what a caller writes through data() goes unchecked; staying inside capacity() is the caller's responsibility. Type safety: an AllocatedSize of 0 fails to compile. Exception safety: no operation throws; exceptions are off in the build.

к сведению

A default-constructed buffer starts with the terminator, so data() reads as an empty string before the first setSize().

к сведению

The bytes between size() and capacity() keep whatever was written there; a shorter length moves the terminator and clears nothing.

FixedStringStorage()​

template <size_t AllocatedSize>
toy::FixedStringStorage< AllocatedSize >::FixedStringStorage ()
 constexpr noexcept

Builds an empty buffer.

Writes the terminator into the first byte and leaves the rest of the buffer uninitialized, so construction costs the same for any AllocatedSize. A constant expression may hold no indeterminate byte, so constant evaluation fills the whole buffer with null characters instead.

Postcondition

size() returns 0, and data() points at '\0'.

reserve()​

template <size_t AllocatedSize>
bool toy::FixedStringStorage< AllocatedSize >::reserve (size_t newCapacity)
 nodiscard constexpr noexcept

Reports whether the buffer holds a string of the requested length.

Allocates nothing and leaves the buffer as it was: the size is fixed at compile time, so the call answers the question a caller would otherwise put to capacity() itself. It is the portable way to make setSize() safe over a storage whose type the caller does not know.

Parameters
newCapacity

Count of characters the buffer must hold, the terminator excluded.

Returns

true when newCapacity is at most capacity(), false when the buffer is too small for it.

Postcondition

capacity() is unchanged, size() keeps the length it reported, and no character in the buffer changes.

к сведению

A storage that owns heap memory grows here; this one answers from the size it was given.

setSize()​

template <size_t AllocatedSize>
void toy::FixedStringStorage< AllocatedSize >::setSize (size_t newSize)
 constexpr noexcept

Records the length of the string in the buffer and terminates it there.

Changes the length only: the characters already in the buffer stay as they are, and the call writes nothing but the terminator.

Parameters
newSize

Count of characters the buffer now holds, the terminator excluded.

Precondition

newSize is at most capacity(), checked by assert_message in debug builds.

Postcondition

size() returns newSize, and the character at that index is '\0'.

к сведению

The buffer never grows: a length past capacity() breaks the precondition instead of reaching for memory, which is where a storage that owns heap memory parts ways with this one.

к сведению

A caller that cannot rule the length out beforehand asks reserve() first, which answers the same question over either storage.
