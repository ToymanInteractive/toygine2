Description​

Application object that holds the version of its build.

Takes a toy::application::Version at construction and keeps a copy. No setter changes the copy; assigning another application replaces the whole object, version included.

Key Features​

Constexpr support: construction and version() evaluate in a constant expression, so the application can be a constexpr object. Explicit construction: a toy::application::Version never converts to an application implicitly. Read-only access: version() returns a const reference, and the class has no setter. No allocation: the object holds one toy::application::Version and nothing else. Process ID: pid() reports the ID of the running process and needs no instance. Thread suspension: sleep() and yield() hand the calling thread back to the scheduler and need no instance.

Usage Example​

 #include "application.hpp"
 
 constexpr toy::application::BaseApplication app{
  toy::application::Version{26, 20, 0, "f7e57d4"},
 };
 
 const uint32_t major = app.version().major;
 const uint32_t processId = app.pid();

Performance Characteristics​

Construction: O(1); copies the version, not the revision characters. Access: O(1); version() returns a reference to the stored copy. Memory usage: the size of one toy::application::Version.

Safety Guarantees​

Lifetime: the stored revision views characters the application does not own, so they have to outlive it; a string literal or other static storage does. Contracts: none; the constructor accepts any version, an empty revision included. Memory safety: nothing allocates; the version lives in the object itself. Exception safety: no operation throws; exceptions are off in the build.

pid()​

uint32_t toy::application::BaseApplication::pid ()
 nodiscard noexcept static

Returns the ID the operating system assigned to the running process.

Each call queries the platform; read the ID once at startup and keep it.

Returns

Process ID, or 0 when the target has no implementation or the system call fails.

к сведению

Returns 0 on Sega MD, Nintendo GBA, Nintendo DS, Nintendo 64, Nintendo GameCube, Nintendo Wii, and Nintendo Wii U, where the build links the stub implementation.

к сведению

On Nintendo Switch, the result holds only the low 32 bits of the 64-bit process ID.
