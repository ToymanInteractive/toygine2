Description​

Major, minor, and patch numbers of a build, with the revision it was built from.

Aggregate the caller fills field by field; every member has a default, so an omitted number reads 0 and an omitted revision holds no characters. The three numbers rank the release. revision names the source of the build, a commit hash or a tag, and settles the order when the numbers match.

Key Features​

Aggregate initialization: no constructor, so designated initializers name the fields at the call site. Constexpr support: construction and both comparisons evaluate in a constant expression. Ordered: equality over all four fields, and a three-way order that reads the numbers first and the revision last. No allocation: three integers and a view; the revision characters belong to whoever created them. Determinism: the order consults no locale and holds across runs and targets. Exception safety: no operation throws; exceptions are off in the build.

Usage Example​

 #include "application.hpp"
 
 const toy::application::Version build{1, 4, 2, "9f3c1ab"};
 constexpr toy::application::Version minimum{.major = 1, .minor = 4};
 
 const bool supported = build >= minimum;

Performance Characteristics​

Construction: O(1) for the numbers; a revision built from a pointer costs one scan for the terminator. Access: O(1); every field is read directly. Equality: O(1) on the numbers, plus O(n) in the length of the revision when all three numbers match. Ordering: O(1) until the first number that differs, plus O(n) in the shorter revision when none does. Memory usage: three 32-bit numbers, then the pointer and length of the view; 32 bytes on a 64-bit target.

Safety Guarantees​

Lifetime: revision views characters it does not own, so the string has to outlive the version. Contracts: none of its own; revision inherits what toy::StringView checks. Memory safety: nothing allocates, and the numbers live in the object itself. Type safety: a nullptr revision meets the deleted constructor of toy::StringView and fails to compile. Exception safety: no operation throws; exceptions are off in the build.

к сведению

A version built without a revision compares equal only to another one that carries none.

operator<=>​

friend std::strong_ordering const Version & lhs, const Version & rhs
 constexpr noexcept

Orders two versions by number, and by revision when every number matches.

Reads the major, minor, and patch numbers in that order and returns at the first one that differs. Three equal numbers hand the decision to the revision, which orders lexicographically by byte.

Parameters
lhs

Version on the left of the operator.

rhs

Version on the right of the operator.

Returns

std::strong_ordering::less when lhs orders first, std::strong_ordering::equal when both hold the same numbers and the same revision, std::strong_ordering::greater when rhs orders first.

к сведению

The compiler synthesizes <, <=, >, and >= from this operator.

к сведению

The order consults no locale, which makes it identical across runs and targets.

внимание

An empty revision orders before every other, so a build that names one orders after the same numbers that name none. Semantic versioning ranks a pre-release the other way.
